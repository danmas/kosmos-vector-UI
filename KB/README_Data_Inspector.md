# Раздел Data Inspector (Инспектор данных)

## Обзор
Data Inspector — это мощный инструмент для просмотра и управления проанализированными элементами кода (AiItems). Предоставляет детальную информацию о каждом элементе на трех уровнях: L0 (исходный код), L1 (связи), L2 (семантика).

## Расположение в UI
- **Иконка**: 🔍
- **Название**: Data Inspector
- **Позиция**: Четвертый элемент в левой панели

## Компонент
- **Файл**: `components/Inspector.tsx`
- **Размер**: 811 строк кода
- **Тип**: React функциональный компонент

## Структура интерфейса

### Левая панель — Список элементов

#### Заголовок и управление
- **Кнопка "Query"** (синяя) — Natural Language Query для поиска элементов
- **Кнопка "Filter"** — Фильтрация по типам и тегам
- **Кнопки "T+" / "T-"** — Массовое добавление/удаление тегов
- **Кнопки "V+" / "V*"** — Векторизация элементов
  - V+ — векторизация только невекторизованных
  - V* — перевекторизация всех

#### Поле поиска
- **Поддержка regex**: Обычный текст или `/pattern/flags`
- **Поиск по**: ID элемента и пути к файлу
- **История поиска**: Выпадающий список с последними запросами
- **Кнопка очистки истории**

#### Список элементов
Каждый элемент отображает:
- **ID элемента** (полужирный моноширинный шрифт)
- **Язык** (маленький серый текст)
- **Тип-бейдж** с цветовой кодировкой:
  - Function — синий
  - Class — изумрудный
  - Method — фиолетовый
  - Module — бирюзовый
  - Interface — розовый
  - Struct — янтарный
  - Table — голубой
  - Table_Column — индиго
- **Теги** (фиолетовые бейджи)
- **Кнопка "T"** — управление тегами элемента
- **Кнопка "V"** — векторизация элемента (меняет цвет при векторизации)

### Правая панель — Детали элемента

#### Заголовок элемента
- **ID** (крупный моноширинный шрифт)
- **Тип-бейдж**
- **Кнопка "EC"** — Extract Columns (только для SQL)
- **Кнопка "T"** — управление тегами
- **Путь к файлу** 📄
- **Язык** 🌐
- **Список тегов** элемента

#### Вкладки детализации

##### Вкладка L0: Source Code (Исходный код)
Компонент: `L0SourceView`
- **Исходный код** элемента с подсветкой синтаксиса
- **Параметры** функции/метода
- **Возвращаемый тип**
- **Строки кода** (startLine - endLine)
- **Docstring** (если есть)

##### Вкладка L1: Connectivity (Связи)
Компонент: `L1ConnectivityView`
- **Зависимости** (dependencies):
  - Список элементов, от которых зависит текущий
  - Типы связей: `calls`, `imports`, `reads_from`, `updates`
  - Кликабельные ссылки для навигации
- **Зависимые** (dependents):
  - Список элементов, которые зависят от текущего
  - Reverse связи (кто вызывает данный элемент)
- **Счетчики**: "X dependencies, Y dependents"

##### Вкладка L2: Semantics (Семантика)
Компонент: `L2SemanticsView`
- **L2 описание**: Сгенерированное LLM описание на естественном языке
- **Пример**: "This function calculates the factorial of a number recursively..."
- **Если нет L2**: Сообщение "L2 enrichment not performed yet"

## Функционал фильтрации

### Natural Query Dialog
- **Назначение**: Поиск элементов на естественном языке
- **Пример**: "Find all functions that work with database"
- **Технология**: LLM преобразует запрос в regex/filter
- **Применение**: Автоматически заполняет поле поиска результатом

### Filter Dialog (Фильтры)
- **Фильтр по типам**: Множественный выбор типов AiItems
- **Фильтр по тегам**: Множественный выбор тегов
- **Кнопка активации**: Меняет цвет на cyan при активных фильтрах
- **Комбинирование**: Фильтры работают вместе с поиском

## Система тегов (Tags)

### Tags Dialog
Модальное окно для управления тегами элемента:
- **Список доступных тегов** из системы
- **Создание новых тегов**: code, name, description
- **Добавление/удаление** тегов к элементу
- **Сохранение**: Автоматическое обновление списка

### Массовые операции с тегами
- **Bulk Add (T+)**: Добавление тегов ко всем отфильтрованным элементам
- **Bulk Remove (T-)**: Удаление тегов у всех отфильтрованных элементов
- **Прогресс**: Показ обработанных элементов
- **Оптимизация**: Batch-обновление для производительности

### API тегов
- `GET /api/items/:id/tags` — получение тегов элемента
- `PUT /api/items/:id/tags` — синхронизация тегов (замена всего списка)
- `POST /api/ai-items/bulk/tags/add` — массовое добавление
- `POST /api/ai-items/bulk/tags/remove` — массовое удаление

## Диалоги и REST API маршруты

Раздел Data Inspector вызывает следующие диалоги.

### 1. NaturalQueryDialog (`components/NaturalQueryDialog.tsx`)

**Вызов**: Кнопка "Query" в левой панели списка элементов.

**Назначение**: Поиск элементов по запросу на естественном языке. Результат применяется к полю поиска Inspector.

| Маршрут | Метод | Описание |
|---------|-------|----------|
| `/api/agent-scripts` | GET | Список сохранённых скриптов-запросов |

| `/api/v1/natural-query` | POST | Запрос: `{ question }` → regex/фильтр |
| `/api/v1/natural-query/suggest` | GET | Похожие вопросы: `?query=...` |
| `/api/agent-scripts/:id` | PUT | Обновление скрипта |
| `/api/agent-scripts/:id/execute` | POST | Выполнение скрипта |

### 2. TagsDialog (`components/TagsDialog.tsx`)

**Вызов**: Кнопка "T" у элемента в списке или в заголовке правой панели деталей.

**Назначение**: Управление тегами элемента; массовые операции (T+/T-) для отфильтрованных элементов.

| Маршрут | Метод | Описание |
|---------|-------|----------|
| `/api/tags` | GET | Список всех тегов |

| `/api/ai-items/bulk/tags/add` | POST | Массовое добавление тегов |
| `/api/ai-items/bulk/tags/remove` | POST | Массовое удаление тегов |
| `/api/tags` | POST | Создание тега: `{ code, name, description }` |

---

### 3. FilterDialog (`components/FilterDialog.tsx`)

**Вызов**: Кнопка "Filter" в левой панели.

**Назначение**: Фильтрация списка по типам и тегам. Общий контекст `GraphFilterContext`.

| Маршрут | Метод | Описание |
|---------|-------|----------|
| `/api/types` | GET | Список типов AI Items |

| Маршрут | Метод | Описание |
|---------|-------|----------|

## Векторизация

### Индивидуальная векторизация (кнопка V)
- **Клик на "V"** у элемента → векторизация этого элемента
- **Изменение цвета**: Серый → Голубой (vectorized)
- **Force mode**: Всегда перезаписывает существующие векторы
- **Индикатор**: Анимация загрузки во время процесса

### Массовая векторизация
- **V+ (Векторизация новых)**: 
  - Обрабатывает только элементы без эмбеддингов
  - Батчи по 5 элементов
  - Прогресс: "X / Y элементов"
- **V* (Перевекторизация всех)**:
  - Обрабатывает все отфильтрованные элементы
  - Force mode (перезапись существующих)
  - Подтверждение при >5 элементов

### Прогресс векторизации
```typescript
interface VectorizeProgress {
  processed: number;
  total: number;
}
```
- Отображение: "Векторизация: X / Y..."
- Анимация pulse для визуальной обратной связи
- Лог в UI Logger

## Extract Columns (EC) — Извлечение колонок

Специальная функция для SQL-функций:
- **Условие**: Только для `language === 'sql'`
- **Назначение**: Парсинг SQL и извлечение колонок таблиц
- **Создание связей**: Автоматическое создание L1 связей к TABLE_COLUMN
- **Отчет**: 
  - Найдено колонок
  - Резолвлено
  - Нерезолвлено
  - Создано связей

## Синхронизация с Graph View

### Двусторонняя связь
- **Из Inspector → Graph**: Фильтр обновляет `filteredItemIds` в контексте
- **Из Graph → Inspector**: Поиск из графа синхронизируется через `inspectorSearch`
- **Контекст**: `GraphFilterContext` для координации

### Контекстная переменная
```typescript
const {
  filteredItemIds,
  setFilteredItemIds,
  inspectorSearch,
  setInspectorSearch
} = useGraphFilter();
```

## Кэширование данных

### DataCacheContext интеграция
- **Первичная загрузка**: Из кэша (если доступен)
- **Вторичная загрузка**: С сервера (если кэш пуст)
- **Индикатор источника**: "Cached" бейдж
- **Автоинвалидация**: При завершении pipeline steps

### Оптимизация загрузки
- **Список элементов** (`AiItemSummary[]`): Метаданные + теги
- **Полные данные** (`AiItem`): Загружаются по требованию при выборе
- **Lazy loading**: Только выбранный элемент

## Технические детали

### Состояние компонента
```typescript
const [itemsList, setItemsList] = useState<AiItemSummary[]>([]);
const [fullItemData, setFullItemData] = useState<AiItem | null>(null);
```

### Regex поиск
Поддержка двух форматов:
- **Простой**: `auth` → поиск подстроки
- **Regex**: `/^auth_.*$/i` → полный regex с флагами

### Фильтрация по тегам
- Проверка пересечения: `item.tags.some(tag => selectedTagCodes.has(tag.code))`
- Комбинирование с фильтром по типам
- Работает вместе с поисковым запросом

## Context-aware
- Автоматическая очистка выбора при смене контекста
- Изоляция списков элементов по context-code
- Сохранение истории поиска глобально (но фильтрация по контексту)
