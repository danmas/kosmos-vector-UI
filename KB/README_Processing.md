# Раздел Processing (Обработка)

## Обзор
Processing — это раздел для управления пайплайном обработки кода. Он трансформирует исходный код в векторизованную базу знаний, готовую для RAG-системы. Состоит из 5 последовательных шагов обработки.

## Расположение в UI
- **Иконка**: ⚙️
- **Название**: Processing
- **Позиция**: Третий элемент в левой панели

## Компонент
- **Файл**: `components/PipelineView.tsx`
- **Размер**: 554 строки кода
- **Тип**: React функциональный компонент

## Этапы пайплайна (Pipeline Steps)

### Step 1: Polyglot Parsing (L0) — Полиязычный парсинг
- **Описание**: Parsing AST for .py, .ts, .go, .java files
- **Назначение**: Разбор абстрактного синтаксического дерева для поддерживаемых языков
- **Выход**: L0 данные (исходный код, структура)
- **Статус**: pending → processing → completed/error

### Step 2: Dependency Analysis (L1) — Анализ зависимостей
- **Описание**: Resolving imports, class hierarchy, and calls
- **Назначение**: Построение графа зависимостей между элементами кода
- **Выход**: L1 связи (calls, imports, inheritance)
- **Автоматически обновляет**: Graph View и Data Inspector

### Step 3: Semantic Enrichment (L2) — Семантическое обогащение
- **Описание**: Generating natural language descriptions via LLM
- **Назначение**: Генерация описаний кода на естественном языке с помощью LLM
- **Выход**: L2 описания (что делает функция/класс)
- **Модель**: Gemini 2.5 Flash (по умолчанию)

### Step 4: Vectorization — Векторизация
- **Описание**: Creating embeddings (text-embedding-ada-002 or Gecko)
- **Назначение**: Создание векторных представлений для семантического поиска
- **Выход**: Векторные эмбеддинги
- **Модель**: Google Gemini text-embedding-004 (по умолчанию)

### Step 5: Index Construction — Построение индекса
- **Описание**: Building FAISS/ChromaDB index
- **Назначение**: Создание оптимизированного индекса для быстрого поиска
- **Выход**: faiss.index файл или ChromaDB коллекция

## Интерфейс управления

### Визуализация шагов
- **Вертикальная временная шкала** с линиями-коннекторами
- **Цветовая индикация**:
  - Серый (pending) — ожидает выполнения
  - Синий + пульсация (processing) — выполняется
  - Зеленый (completed) — завершен
  - Красный (error) — ошибка
- **Иконки статуса**:
  - Номер шага (1-5) — pending
  - ↻ (rotating) — processing
  - ✓ — completed
  - ! — error

### Запуск шагов
- **Клик на иконку шага** — запуск отдельного шага
- **Кнопка "Run Simulation"** — запуск всего пайплайна последовательно (для демонстрации)
- **Автоматическое открытие логов** при старте выполнения

### Результаты выполнения
- Кнопка "Результат" появляется после завершения шага
- Отображение JSON-отчета с метриками:
  - Количество обработанных элементов
  - Количество созданных связей
  - Время выполнения
  - Ошибки (если есть)
- Возможность скачать результат как JSON

## Конфигурация пайплайна

### Configuration Panel (правая панель)
Редактируемые настройки с автосохранением:

#### Embedding Model (Модель эмбеддингов)
- **Google Gemini** (text-embedding-004) — по умолчанию
- OpenAI (text-embedding-3-small)
- Local (SentenceTransformers)

#### Chunk Strategy (Стратегия разбиения)
- **Semantic (AiItem/Function-based)** — по умолчанию, сохраняет контекст
- Fixed Size (512 tokens) — фиксированный размер
- File-based — целые файлы

#### LLM Model (Enrichment) — Модель для обогащения
- **Gemini 2.5 Flash** — по умолчанию
- Gemini 1.5 Pro
- GPT-4o

### Автосохранение конфигурации
- Индикатор "Saving..." при изменениях
- Сохранение в `pipeline-configs.json` через API
- Применяется при следующем запуске шагов

## How Vectorization Works (Информационная панель)

Объяснение процесса векторизации:

1. **Chunking** — Код разбивается не построчно, а по AiItems (функциям/классам)
2. **Description Generation** — LLM генерирует резюме кода (L2)
3. **Embedding** — Резюме + сигнатура отправляются в Embedding Model
4. **Storage** — Векторы сохраняются в `faiss.index` для быстрого поиска

## Статус шагов и автообновление

### Polling механизм
- **Интервал**: 2 секунды
- **Endpoint**: GET `/api/pipeline/steps/status`
- **Автоматическое обновление** статусов всех шагов
- **Маппинг статусов**:
  - `running` → `processing`
  - `completed` → `completed`
  - `failed` → `error`

### Автоматическая инвалидация кэша
При завершении шага (processing → completed):
- Автоматически вызывается `invalidate()` для DataCacheContext
- Запускается `prefetchAll()` для перезагрузки данных
- Обновляются все зависимые компоненты (Inspector, Graph)

## Интеграция с Server Logs
- Автоматическое открытие диалога логов при старте шага
- Режим открытия настраивается через `VITE_SERVER_LOGS_OPEN_MODE`
- Передача context-code для фильтрации логов

## Диалоги и REST API маршруты

### 1. ServerLogsDialog (`components/ServerLogsDialog.tsx`)

**Вызов**: Автоматически открывается при запуске шага пайплайна (если `VITE_SERVER_LOGS_OPEN_MODE=dialog`). Также кнопка 📟 Server Logs в sidebar.

**Назначение**: Просмотр логов сервера в реальном времени. Содержит `LogViewer` с EventSource.

| Маршрут | Метод | Описание |
|---------|-------|----------|
| `/api/logs/stream` | EventSource (GET) | SSE-поток логов в реальном времени. Порт: VITE_BACKEND_PORT (по умолчанию 3200) |

**Сохранение**: Размер и позиция диалога сохраняются в localStorage (`serverLogsDialog_state`).

---

### 2. Диалог подтверждения очистки БД (inline в PipelineView)

**Вызов**: Кнопка "Очистить БД" — открывает модальное окно подтверждения.

**Назначение**: Подтверждение необратимой операции удаления векторной базы.

| Маршрут | Метод | Описание |
|---------|-------|----------|
| `/api/vector-db` | DELETE | Очистка векторной БД. Response: `{ success, message, deletedFiles?, errors? }` |

### REST API раздела Processing

| Маршрут | Метод | Описание |
|---------|-------|----------|
| `/api/pipeline/context-definition` | GET | Определения шагов пайплайна |
| `/api/pipeline/context-config` | GET | Конфигурация контекста (модели, стратегии) |
| `/api/pipeline/context-config` | POST | Обновление конфигурации |
| `/api/pipeline/step/:id/run` | POST | Запуск конкретного шага |
| `/api/pipeline/steps/status` | GET | Статусы всех шагов (polling каждые 2с) |

## Стилизация
- Вертикальная временная линия с коннекторами
- Адаптивная двухколоночная сетка (steps + config)
- Анимация прогресса для processing состояния
- Градиентные кнопки с hover-эффектами

## Context-aware
- Каждый context имеет свою конфигурацию пайплайна
- Историярасков изолирована по context-code
- Статусы шагов сохраняются независимо
